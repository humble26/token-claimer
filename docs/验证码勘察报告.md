## 二、结论摘要

1. **验证码家族：拖动拼图滑块（是）**。可直接观测到的文本证据：`请完成安全验证`、`拖动滑块完成拼图`、`刷新验证码`、`CertifyId: 43CTJ6FnKg`。其中 `CertifyId` 是**阿里云验证码**（阿里云 NoCaptcha）的特征字段，故判定为**阿里云滑块拼图**。不属于旋转/点选/推理类。
2. **容器：应用内浮层，不是独立窗口**。验证码全部元素都挂在 ZCode 同一个顶层窗口（`0x3079c`）下，是 Electron 渲染进程里的一个居中模态浮层，窗口内未出现第二个可见窗口。
3. **交互通道**：
   - UIA：能拿到浮层的**文本元素**和**图片元素的包围盒**，但**拿不到像素**（`ct50006` 图片元素的 accessible name 是 Chromium 的占位文案"要获取缺失的图片说明，请打开上下文菜单。"）。
   - CDP：ZCode 是标准 Electron 41.0.3；但存在**应用级单实例锁**，第二个实例会被直接顶掉（实测 exitcode=0），所以调试端口**只能由"本工具启动的那一次"带上**。当前运行实例未带端口，`127.0.0.1:9223` 无响应。
   - 屏幕截图：**桌面 DC 的 BitBlt 可用**（已成功抓到 ZCode 画面）；**窗口 DC 的 BitBlt 对 GPU 渲染的 Electron 返回全黑**，故路线 B 必须"抓全屏再按 UIA 包围盒裁剪"。
4. **架构决策：路线 B（屏幕截图 + SendInput）**，理由见 §六。

## 三、验证码形态与几何（来自历史 dump，实测观测）

来源：`logs/ui_dump_zcode_after_banner2.txt`（当次窗口 1707x1019 逻辑像素，侧栏宽 264）。

```
[ct50020] 请完成安全验证          @(703,316) 113x21     ← 浮层标题
[ct50000] "关闭验证"             @(975,311)  29x31     ← 关闭按钮
[ct50006] 要获取缺失的图片说明…    @(703,350) 301x201    ← 拼图区（图片元素，唯一）
[ct50000] 刷新验证码             @(971,350)  33x33     ← 刷新（拼图区右上角）
[ct50020] 拖动滑块完成拼图        @(793,567) 121x22     ← 滑块轨道上的提示文案
[ct50020] (无名字)              @(715,571)  17x17     ← 疑似滑块手柄（轨道最左）
[ct50020] CertifyId: 43CTJ6FnKg @(703,603)  63x8      ← 阿里云验证码标识
```

同时侧栏底部的领取入口显示 `[ct50000] 打开 @(16,865) 236x96 [禁用]` + `[ct50020] 正在验证… @(231,887)`，即**验证码正在等待处理时，领取按钮呈禁用并显示"正在验证…"**。

由以上可推导（推断，待实测确认）：

- 浮层是 301 宽的一列：标题(316) → 拼图区(350, 301x201) → 滑块轨道(≈560~590) → CertifyId(603)。
- 拼图区宽 301，与滑块轨道可视宽度一致 → **拖动距离可直接由 `gap.x`（拼图区像素）换算，缩放系数≈1**（仍需按实际显示宽度/自然宽度校准）。
- 拖动起点≈滑块手柄中心 (715+8, 571+8) = **(723, 579)**（旧窗口坐标，仅作量级参考）。

> ⚠️ **坐标不可硬编码**：本次实测 ZCode 窗口已是 2561x1529（侧栏 396 宽），与历史 dump 的 1707x1019（侧栏 264）不同。集成时必须**每次从实时 UIA 树取浮层几何**，不能写死像素。

### 拼图块与背景图的获取方式

- UIA 侧只有**一个**图片元素（301x201），覆盖整个拼图区，**无法把背景图与拼图块分开**。
- 因此：
  - 路线 A（CDP）下可查 DOM（canvas/img）分别取图 —— 未实测。
  - 路线 B（屏幕截图）下只能拿到**合成图**：背景（含缺口）+ 左侧拼图块。拼图块裁剪规则（起始 x/y、尺寸）**必须实测标定**；标定前可先用 `find_gap(bg, piece=None)` 的 `edge_only` 兜底路径。

### 成功判定信号（候选，未实测）

- 浮层整体消失（`请完成安全验证` / `拖动滑块完成拼图` 元素不再出现）；
- 侧栏领取入口从 `[禁用] 正在验证…` 变为可用，随后消失（表示已领取）；
- 失败时通常会出现"验证失败/请重试"类文案（本 dump 未捕获到，待实测）。

## 六、架构决策

### 候选对比

| 维度 | 路线 A：CDP + Playwright | 路线 B：屏幕截图 + SendInput |
| --- | --- | --- |
| 取图质量 | 好：可分别取 canvas/img，背景与拼图块天然分离 | 一般：只能取合成图，拼图块需裁剪标定 |
| 输入通道 | CDP 鼠标事件，窗口可被遮挡 | SendInput，需窗口可见、不可被遮挡 |
| 新增依赖 | **需在 3.14 装 playwright**（3.14 兼容性未验证，且是重量级依赖） | **零新增**（numpy+opencv 已具备；SendInput 用 ctypes，`uia_click.py` 已有先例） |
| 对 ZCode 启动的影响 | 必须由本工具带 `--remote-debugging-port` 启动；用户已在用 ZCode 时无 CDP | 无影响，沿用现有 `--force-renderer-accessibility` 启动方式 |
| 可行性证据 | **未证实**：单实例锁使端口只能由主实例携带，而主实例当前未带、且不可重启 | **已验证**：桌面 BitBlt 可抓到 ZCode 画面；UIA 可提供浮层几何 |
| 附加风险 | 常开调试端口是一个额外的本地攻击面 | DPI/遮挡敏感（已有 `system_dpi_scale()` 与全屏抓图兜底） |

### 决策

**采用路线 B（屏幕截图 + SendInput）**。依据是文档给出的路线 A 触发条件是"CDP 可用且能定位到验证码所在页面/iframe"，而本次勘察**无法证实 CDP 可用**（单实例锁 + 主实例不可重启 + 3.14 上 playwright 缺失），路线 B 则**零新增依赖且关键能力已验证**。

同时保留升级路径：`config.json` 的 `captcha.route` 字段留出 `cdp` 取值。若后续实测证明"本工具启动的 ZCode 能开出 9223 且 3.14 能装 playwright"，可平滑切到路线 A。

### 路线 B 的实现骨架（与传输层无关的部分全部复用现成库）

1. **定位浮层**：UIA 树里找 `请完成安全验证` / `拖动滑块完成拼图` / `刷新验证码` 任一 → 取拼图区图片元素包围盒与滑块手柄中心（全部来自实时树，不写死坐标）。
2. **取图**：DPI 感知全屏 BitBlt → 按拼图区包围盒（逻辑坐标 × `system_dpi_scale()`）裁剪 → 得合成图。
3. **定位缺口**：`find_gap(bg, piece)`；拼图块裁剪规则标定前先用 `find_gap(bg, piece=None)`（`edge_only`）兜底。
4. **拖拽**：`build_choreography(distance)` → SendInput 解释 `('down',)/('move',x,y)/('up',)/('sleep',ms)`，起点=滑块手柄中心物理坐标。
5. **判定**：浮层元素消失视为成功；失败按 `max_attempts` 重试，次间随机 ≥2s；连续失败进入冷却并回退人工。
6. **回退**：任何失败/超时都不阻塞领取主流程，日志记"验证码需人工处理"，等下个调度周期。
